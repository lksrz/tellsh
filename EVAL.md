# tellsh evaluation (v0.4 model)

Generated by `npm run eval`, `npm run bench` and `node scripts/teacher.js report` (teacher section).

**v0.3 close (round 24, 2026-10-11): two design rules instead of more special cases** (model unchanged, regression tests
in `test/regressions25.test.js`, `test/allowlist.test.js`). (1) *Selector rule* for gh / wrangler: a request is read
against a closed vocabulary; a word nothing explains withholds the selector as a placeholder (`<PR>`, `<WENV>`, `<NUM>`,
`<ARGS>`), never a guess and never a bare command. This fixes the four round-23 majors (`deploy worker in preview2`,
`set worker secret API_KEY --env staging`, `install the project dependencies with npm`, `create a pull request in repo
acme/app`) and an excluded environment (`deploy worker but not to production`). (2) *Allowlist danger checker*: only
the commands / subcommands / flags the catalog renders (all shells, generated) are trusted; a wrapper (incl. `sudo`), an
environment assignment, an unknown program, subcommand or flag is high risk. Measured effect:

| measurement | before | after |
|---|---|---|
| public `npm run eval` sections (intent, slots, e2e relex, history, composer, OOD) | — | byte-identical |
| dev-tools eval `data/eval_v04/devtools.jsonl`, exact command (rows with `expect_command`) | 288 / 324 | 294 / 324 |
| gh / wrangler phrasings (train + dev-tools eval, 1097) ending in a placeholder | 57 | 103 |
| catalog renders, 173 intents x 6 shells: safe / medium / high | 643 / 290 / 69 | 643 / 263 / 96 |
| composer commands on `data/compose/eval.jsonl` that are high risk | 0 / 43 | 0 / 43 |
| warm latency p50 (bash, composer off) | 0.409 ms | 0.421 ms |

The 27 renders that became high are all `sudo` templates (service start/stop/restart/enable, `apt install` / update,
`chown`, `dmesg`, macOS `powermetrics`): `sudo` is a wrapper. The v0.4 section below (real-usage data, hybrid encoder)
was not regenerated: it needs the private dataset and the encoder; the selector rule changes only gh / wrangler /
`npm install` slots, which that report does not score separately.

**v0.3 close, final-review majors (2026-10-11)** (model unchanged, regression tests in `test/regressions26.test.js`).
(1) A command substitution `$(…)` / `` `…` `` anywhere outside '…' (also inside "…", e.g. `ls "$(rm -rf ~)"`, which was
safe) and a process substitution `<(…)` / `>(…)` are high risk; `$((…))` arithmetic is not a substitution. (2) Only
allowlisted programs are safe: the "expression fragment" exemption is gone (`7z …`, `.hidden …` were safe) and a program
is matched as written, so a path (`./ls`, `/tmp/x/ls`, `C:\t\ls.exe`) is not the allowlisted `ls`. The pieces of the
catalog's PowerShell expressions (`$_.Name`, `.Count`, `[math]::Round`) are recorded in the generated allowlist like
programs; a number, an argument-list item (`'a',`) and `$env:NAME` are matched by shape. (3) An explicit wrangler `--env`
no longer drops the other unexplained words: `deploy worker --env staging --config other.toml` is
`npx wrangler deploy --env staging <ARGS>` (was `… --env staging`, nothing missing). (4) Competing repositories are
withheld even beside an explicit pull request: two `--repo`, `a/b or c/d`, `a/b#42 --repo c/d`, or a pull request URL of
another repository than `--repo` give `--repo <REPO>`. Two templates changed so the catalog stays on the allowlist:
Linux `battery` reads `upower -i /org/freedesktop/UPower/devices/DisplayDevice` instead of `"$(upower -e | grep …)"`
(bash and fish), and the PowerShell `journal_service` filter is `-Match ([regex]::Escape(…))` instead of
`-Like ('*' + … + '*')` (a bare `*` in the allowlist would have trusted a glob as a program). Measured: public
`npm run eval` sections byte-identical; dev-tools eval exact 294 / 324 before and after; of all catalog renders only
these two templates changed (the PowerShell `journal_service` with a `<SERVICE>` placeholder went medium -> safe: the old
`<SERVICE>` inside `( … )` was read as a redirect); `docker stop $(docker ps -q)` was already high.

### Known limits

* The selector vocabulary is closed and hand-written (EN/PL): harmless paraphrases with an unlisted word get a
  placeholder (46 more of the 1097 phrasings above), and options the commands do not render (`--draft`, `--base`,
  `--label`, `--state`, `--squash`, `--port`, `--hostname`) always become `<ARGS>`. A selector hidden in a listed word
  is not caught (`merge the pr into main` stays `gh pr merge`).
* The rule covers gh / wrangler (and `npm install` dependency words) only; other intents keep their per-slot parsers.
* The allowlist knows only what the catalog renders: a safe edit with an unseen flag (`git log --stat`) is high and needs
  `yes`. Any `$(…)`, backtick or `<(…)` is high, also a
  harmless one typed in an edit (`echo "$(date)"`); a backtick in a PowerShell edit (its escape character) is high too.
  Every `sudo` catalog command is high.
* Dev-tools exact-match losses against the gold: `show live logs from the worker in production` is now
  `npx wrangler tail --env production` (gold: no `--env`), Polish `z produkcji` / `na produkcji` give `--env <WENV>`.

**v0.4 model (2026-10-10): 24 developer-tool intents + private real-usage training data.** Catalog 149 → 173
intents (npm/pip/venv, `--version`/`--help`, line ranges, SSH port forwarding, wrangler, gh). A is retrained on the
public data plus a capped, half-weighted train split of a private real-command dataset (held out by command group;
see [HYBRID.md](HYBRID.md#v04-real-usage)); thresholds are calibrated on curated rows only (accept 0.34 → 0.375).
The sections below are the regenerated public metrics. Against v0.3 on public sets the retrained A is slightly
worse: intent top-1 on `data/eval` 95.6% → 95.4%, end-to-end relex 85.3% → 83.4%, hand-written slot cases 99 → 98/99,
composer any-acceptable 52.9% → 49.0% (dev) and 22.4% → 17.2% (blind), OOD rejection 94.6% → 92.4%, blind OOD
100% → 98.4%, model 2.71 → 2.95 MB. In exchange, real-usage intent accuracy goes from 31.6% to 82.0% (A) and 88.8%
(A+B, retrained encoder of round 8, recalibrated on the leak-free A_dev of round 9), and the new intents reach 95.8% on an independently written eval set — see the v0.4 section at the end.
Two composer fixes: no composed command for a value with a line break or for a place reference ("list files there").

**v0.3.0 (2026-10-10), after three review rounds.** The model is **retrained** on the v0.3 data (31534 classifier
rows, 34434 tagged sequences; teacher-labelled paraphrases and hard negatives; every held-out text, its near-duplicates
up to filler words and word order, and its contrastive rewrites excluded at emission time), and
`model/compose_explained.json` is rebuilt from the same rows. Runtime fixes from the reviews (all with regression
tests in `test/regressions*.test.js`): refused or ambiguous history references and paths with trailing punctuation
stay placeholders and never fall back to a catalog default (`find . … -delete`); "same for X" never replays an older
changing command or a cut path; a searched, filtered or (for "them") listed directory is never a deletion target;
typed references follow recency; quoted `'~/x'` from history stays literal; more danger-checker wrappers. Against the
v0.2 numbers: end-to-end 82.8% → **85.3%**, composer "any answer acceptable" 31.4% → **52.9%**, out-of-domain
rejection 92.4% → **94.6%**; history references unchanged at 97.9% (dev set). cmd renders 114/149 intents natively
(117 in v0.2: a value starting with `/` is now refused where cmd.exe would read it as a switch, so the eval rows
for `dir_size`, `chown` and `create_symlink`, which use POSIX paths like `/var/www`, report a gap).

**Round 4b (stricter history rules, model unchanged).** `gen_data.js` output is byte-identical to the build the shipped
model was trained on (31534 / 34434), so the model was not retrained; `teacher.js` (Jev) now uses the same exclusion
index as `gen_data.js` (`exclusionIndex`: held-out texts, near-duplicates, contrastive rewrites **and** eval-only slot
values). A changing command (rm, mv, cp source/destination, kill, chmod, git branch -d/checkout, docker exec/stop,
service restart, …) now takes a history value only when it is unambiguous and the newest value of its type: never a
listed or searched directory (also for "it"), never an older value, never a value a newer listing of the same type may
have replaced, never a `cd` directory after which other commands ran. This lowers the history numbers on purpose:
dev 97.9% → **91.7%** (3 rows expected an older branch after `git checkout main`: "delete that branch", "usuń tę gałąź",
"switch back to that release branch"), blind 82.3% → **79.7%** (an older branch after `git checkout main`; a container
before a newer `docker ps`); every one of these now renders a placeholder instead. The danger checker now unwraps any
`-c`/`--command` payload, checks the command at every later word after a wrapper, and rates unreadable payloads
(`sh -c "$X"`, `$CMD …`, `… | sh`) high. Function words never turn a path into `.` ("list files in the" → `<PATH>`).
Benchmark re-run on a busier machine (bare `node` startup 75 → 86 ms).

**Round 7 (one line of history, model unchanged).** History references now read **only the single most recent
command** ("delete it", "same for /var", "there" never reach an older line; the running `tellsh` call that zsh/fish/
PSReadLine write first is dropped). When that line does not name a value of the needed type, or cannot be read, the
reference is refused and the slot stays a placeholder. Gold rows whose meaning changed: dev `["sudo systemctl stop

tuned on) `[… "git commit -m 'wip'"]` + "push it" → `git push` and `["git checkout hotfix/tz-offset", "git log -n 3"]`
+ "delete that branch" → `git branch -d <BRANCH>`. 5 dev rows added (a value two lines back is never used; their
queries were already held out, so `gen_data.js` output is unchanged). Dev 91.7% (48) → **92.5%** (53); blind 79.7% →
**82.3%** (both gained rows are rule fixes, not gold edits: "ssh to that host again" after `history | tail` and
"wejdź do tamtego kontenera" after `docker ps -a` now give the expected placeholders; the 2 edited rows were correct
under the old gold and are correct under the new one). Round-6 fixes:
quoted paths with spaces keep their boundaries (CLI argv and earlier `tellsh` lines), invalid history values and refused
references never become `.`, more place wordings ("the previous folder", "the directory I listed", "w poprzednim
katalogu"), "its contents"/"usuń jego zawartość", `git -C`/`docker --context` before a listing, "move it there", several

files, NUL bytes. Every other eval number is unchanged. Bench: the history case is 1.6 → 0.7 ms p50 (one line parsed).

**Round 8 (review r7; A unchanged, B retrained).** Quoted request text passed as several arguments is no longer read as
a path (`tellsh "delete folder" /tmp/x` → `rm -r /tmp/x`; a quoted argument that is neither a path nor the first word,

dropped from history only on an exact match. Several operands (`touch a.txt b.txt`) are never "it"/"them"; `cat a.txt;
cd /srv` + "delete it" is refused; "move it there" is refused with a note. Deleting, editing in place or overwriting a
system file (`rm /etc/passwd`, `sed -i d /etc/passwd`, `… | tee /etc/passwd`) is critical. The composer never fills a
slot the catalog withheld (`` `pwd` ``, a line break). npm scoped packages (`@types/node`) are kept, an invalid package
operand is a placeholder. `fetch_model.js` installs only the bundle's own file names. `export_data.js` now filters
augmented rows against the held-out index (143 leaked copies): B was retrained and recalibrated (see HYBRID.md); the
hybrid re-ranks the policy's 5 candidates whatever `--top` shows. Every eval number of A is unchanged; the v0.4 devtools
exact command (A) is 90.7 → 91.0% (scoped packages). `ls /a /b` + "show it" now gives a placeholder (test updated).

**Round 11 (review r10; A unchanged, A+B policy unchanged).** A login shell runs in the target user's home, so
`sudo -i` / `--login` (also in a cluster: `sudo -iu bob`), `runuser -l` and `su -` make relative history values
